# Trap Chess Bot

Android-приложение: смотрит на шахматную доску через трансляцию экрана, считает ход встроенным движком на Java
(с «ловушками») и сам нажимает на клетки. Плавающие кнопки: **A** — авто-режим, **1** — один ход, **Б/Ч** — быстро сменить сторону (кто внизу доски), **▣** — рамка.

## Как собрать APK на GitHub
1. Создайте репозиторий и загрузите в него **содержимое этой папки** (включая скрытую `.github`).
2. Вкладка **Actions** → workflow **Build APK** запустится сам (или «Run workflow»).
3. После зелёной галочки откройте запуск → **Artifacts** → `TrapChessBot-apk` → внутри `app-debug.apk`.
4. Установите APK на телефон (разрешите установку из неизвестных источников).

Если сборка упала — откройте лог шага «Build debug APK» и пришлите ошибку.

## Как пользоваться
1. Откройте приложение → «Включить службу доступа» → включите **Trap Chess Bot**.
   Android 13+: если пункт серый — Настройки → Приложения → Trap Chess Bot → ⋮ → «Разрешить ограниченные настройки».
2. Выберите цвет, который **внизу доски на экране**, глубину (1–100), время на ход (0.1–100 с), хитрость.
3. «Запустить» → разрешите трансляцию **всего экрана** (не «одного приложения»).
4. Откройте шахматное приложение с **начальной позицией**. Наведите жёлтую рамку на доску
   (двигать — тянуть за рамку, размер — за правый нижний угол), нажмите **«Запомнить»** — рамка сама подгонится по сетке клеток, — затем **«Готово»**.
   Фигуры запоминаются один раз для вашей темы оформления (сохраняются в телефоне).
5. **A** — авто-режим: бот ждёт вашей очереди и ходит сам. **1** — один ход. **▣** — снова показать рамку.
   Кнопки можно перетаскивать (место запоминается); ставьте их вне доски. В настройках есть «Видимость кнопок»: 0% — полностью невидимы, но нажимаются.

## Ограничения
- Распознавание учится по начальной позиции: при смене темы фигур/доски нужно снова нажать «Запомнить».
- Превращение пешки всегда в ферзя (второй тап по полю превращения).
- Рокировку бот определяет по расстановке; права на неё отслеживаются по ходу партии.
- Не используйте в рейтинговых онлайн-партиях: это нарушает правила честной игры платформ и ведёт к бану.

## Что нового (v4.1)
- **По умолчанию — начальная позиция шахмат.** При запуске бот сразу считает, что на доске стартовая позиция (ход белых); если на экране начальная расстановка — позиция сбрасывается к ней в любой момент.
- **Кнопка A заново сканирует доску.** При каждом включении авто-режима бот пересобирает позицию с экрана (в том числе с середины партии, если вы ходили сами или партия продолжилась без бота), сбрасывает «ожидание хода соперника» и затем ходит. Если расстановка на экране совпала с ведомой партией, типы фигур и права рокировки берутся из неё (надёжнее силуэтов); если силуэты не читаются — бот пробует догнать позицию по ведомой партии и сообщает, если не получается. «Б/Ч» теперь тоже запускает такую пересборку.
- **Многопоточность под 8 ядер (MediaTek Dimensity 1080: 2×A78 + 6×A55).** В авто-режиме движок берёт все ядра, до 8 (раньше максимум 6). Главный поток поиска получает наивысший приоритет, помощники — повышенный, чтобы планировщик ставил их на большие ядра; если система не разрешает, приоритет откатывается к безопасному. Задачи анализа ловушек раздаются динамически: быстрые ядра берут больше, медленные — меньше. В настройках появилось поле «Потоки движка» (0 = авто; применяется при запуске бота) — можно, например, поставить 2–4, если телефон перегревается.
- **Время на ход — число или диапазон.** В поле можно написать `3`, `0.1-1`, `5-6`, `0.1-50` и т. п. (от 0.1 до 100 с). Для диапазона на каждый ход берётся случайное время из него (шаг 0.1 с). Старая настройка подхватывается как одно число.
- **Хэш-таблица движка 64 МБ** (было 8 МБ). Если на телефоне не хватает памяти, размер автоматически уменьшается вдвое, пока не поместится; в манифесте включён `largeHeap`.

## Что нового (v4)
- **Король и ферзь больше не путаются.** Бот сам ведёт партию: тип каждой фигуры известен с начальной позиции и меняется только законными ходами. С экрана читается лишь «пусто / белая / чёрная» (это надёжно). Силуэты нужны только если бота включили посреди партии. Проверено на 40 симулированных партиях с намеренно перепутанными королём/ферзём на «картинке» — 0 ошибок (включая рокировки, взятие на проходе, превращения, пропущенные кадры).
- Права рокировки и взятие на проходе теперь берутся из ведомой партии и передаются движку.
- Сильнее игра: в оценку добавлена подвижность коня, слона, ладьи и ферзя. Матч 40 партий против v3 (100 мс/ход, 1 ядро, без «хитрости»): +18 =9 −13 (≈56%).
- Если включаете бота посреди партии, лучше выбрать момент, когда король и ферзь различимы; надёжнее всего начинать с начальной позиции.

## Что нового (v3) — движок переписан на Java
- Чистая Java вместо JS в WebView: без WebView и мостов JS↔Java. Скорость на одном ядре измерена: ≈1,1–1,4× узлов/с к старому JS, а дерево поиска меньше (отсечения LMR/futility), поэтому глубина 9 достигается заметно быстрее.
- Многопоточность: поиск лучшего хода идёт на всех ядрах (Lazy SMP, общая таблица), анализ ловушек — тоже параллельно.
- Ловушки теперь считаются по ВСЕМ ответам соперника (а не по трём): для каждого хода-кандидата находится
  гарантированный результат (худший ответ), ожидание против живого игрока и **шанс ошибки соперника** (показывается в подсказке).
  Модель соперника учитывает, что люди чаще берут/перебивают, ставят шахи и убирают атакованные фигуры.
- Вилки: проверяется, что вилочная фигура не висит; считаются шах+угроза, вскрытые атаки и «угроза вилки» (тихий ход,
  после которого следующий ход — безопасная вилка). Раньше «вилка» засчитывалась и для фигуры, которую просто брали бесплатно.
- Связки/скрепления, запертые фигуры — сохранены и усилены; риск ответной вилки соперника вычитается.
- Исправлено: кандидаты сравнивались на разной глубине (поиск мог выбрать заметно худший ход как «ловушку»);
  поиск взятий не разбирал шахи (пропускал маты и шахи-вилки); проверка безопасности вилки не учитывала защиту.
- Если вас прижали (оценка < −1,5 пешки), допуск на риск автоматически растёт — бот «играет на обман».
- Самопроверка: `tools/PerftTest.java` (генератор ходов сверен с эталонными perft), `tools/Match.java` (матч против старого JS-движка).

## Что нового (v2)
- Движок: проверка позиции и прав рокировки, история партии, связки/вилки/ловушки, запрет ходов, которые не получились.
- Распознавание: у каждой стороны ровно один король (ферзь/король больше не путаются).
- Нажатия: нижний ряд доски не попадает в зону системных жестов; при неудаче — другая последовательность, затем перетаскивание, затем другой ход.
- Бот, включённый посреди партии, ждёт хода соперника, если его ход не проходит.
